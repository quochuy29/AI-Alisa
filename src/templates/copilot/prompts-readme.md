# Copilot Prompt Files

> **Tip:** Use the orchestrator agent [`@Requirements Manager`](../agents/README.md) instead of invoking prompts directly — it guides you through the full workflow step-by-step.

This directory contains 13 prompt files for VS Code GitHub Copilot Agent Mode, generated by `requirement-commands`.

---

## Quick Start

```
1. Open Copilot Chat  (Ctrl+Shift+I)
2. Switch to Agent Mode
3. Select @Requirements Manager  ← orchestrator, handles routing for you
   — or —
   Type #prompt:requirements-start <feature description>  ← invoke directly
```

## Lifecycle Overview

```
 #prompt:requirements-start
        │  phase: discovery → context → detail → requirements_complete
        ▼
 #prompt:requirements-specs-generate
        │  phase: specs_generated → design_approved → specs_complete
        ▼
 #prompt:requirements-specs-execute  ──(repeat per task)──┐
        │  phase: executing                                │
        │◄─────────────────────────────────────────────────┘
        │  phase: implemented
        ▼
 #prompt:requirements-code-review   (optional)
 #prompt:requirements-revise        (optional)
        │
        ▼
 #prompt:requirements-end
        │  session archived

  Side-tracks (available at any phase):
  ├── 🐛  #prompt:requirements-bug-fix
  ├── 🔄  #prompt:requirements-spec-enhance
  ├── 📊  #prompt:requirements-status
  ├── 📋  #prompt:requirements-current
  ├── 📖  #prompt:requirements-remind
  └── 📚  #prompt:requirements-library
```

## Prompt Reference

### Stage 1 — Capture

#### `#prompt:requirements-start`
> Begin gathering requirements for a new feature

**Usage:**
```
#prompt:requirements-start add Google OAuth login
```
**Argument:** Feature description (required)
**Tools:** `search/codebase`, `edit/editFiles`, `execute/runInTerminal`, `execute/getTerminalOutput`, `vscode/askQuestion`
**What it does:**
- Runs a 2-phase PM interview (5 questions per phase) using `vscode/askQuestion`
- Autonomously analyses the codebase between phases
- Generates files `00` through `06` under `requirements/YYYY-MM-DD-HHMM-slug/`
- Updates `metadata.json` → `phase: requirements_complete`

**Next step after completion:** `#prompt:requirements-specs-generate`

---

### Stage 2 — Design & Plan

#### `#prompt:requirements-specs-generate`
> Generate design document and implementation task breakdown

**Usage:**
```
#prompt:requirements-specs-generate
```
**Tools:** `search/codebase`, `edit/editFiles`, `vscode/askQuestion`
**What it does:**
- Reads completed requirements files `00–06`
- Generates `07-design.md` (architecture, components, data models)
- Asks for design approval via `vscode/askQuestion`
- Generates `08-tasks.md` with atomic, ordered implementation tasks
- Updates `metadata.json` → `phase: specs_complete`

> **Recommended:** Run in a **fresh Copilot Chat session** for best task quality.

**Next step after completion:** `#prompt:requirements-specs-execute`

---

### Stage 3 — Implement

#### `#prompt:requirements-specs-execute`
> Execute implementation tasks from the task breakdown

**Usage:**
```
#prompt:requirements-specs-execute
```
**Tools:** `search/codebase`, `edit/editFiles`, `execute/runInTerminal`, `execute/getTerminalOutput`, `read/problems`
**What it does:**
- Parses the next pending task from `08-tasks.md`
- Prepares optimised context (only relevant files)
- Implements the code, runs verification checks
- Asks for approval before marking task complete
- Updates `metadata.json` → `phase: executing / implemented`

**Repeat** for each task. After all tasks → `#prompt:requirements-code-review`

---

### Stage 4 — Quality (optional)

#### `#prompt:requirements-code-review`
> Perform technical code review with eight-pill analysis

**Usage:**
```
#prompt:requirements-code-review
#prompt:requirements-code-review src/auth/   ← review specific path
#prompt:requirements-code-review --depth thorough
```
**Tools:** `search/codebase`, `execute/runInTerminal`, `execute/getTerminalOutput`, `read/problems`
**What it does:**
- Runs eight quality dimensions: correctness, security, performance, maintainability, testability, design patterns, error handling, documentation
- Produces a scored report with actionable findings

#### `#prompt:requirements-revise`
> Check alignment between implementation and requirements/design

**Usage:**
```
#prompt:requirements-revise
```
**Tools:** `search/codebase`, `execute/runInTerminal`, `execute/getTerminalOutput`
**What it does:**
- Compares committed code against `02-discovery-answers.md`, `05-detail-answers.md`, and `07-design.md`
- Detects scope drift and untracked changes
- Scores task coverage and flags deviations

---

### Stage 5 — Close

#### `#prompt:requirements-end`
> Complete and archive the current requirement session

**Usage:**
```
#prompt:requirements-end
```
**Tools:** `edit/editFiles`, `execute/runInTerminal`, `execute/getTerminalOutput`
**What it does:**
- Validates no active bugs or changes are open
- Offers: Archive (complete), Mark incomplete, Cancel & delete, Keep active
- Moves session folder to `requirements/archived/`
- Clears `.current-requirement`

### Side-tracks

#### `#prompt:requirements-bug-fix`
> Fix implementation issues using the two-step Analyze → Fix method

**Usage:**
```
#prompt:requirements-bug-fix login fails with + in email
```
**Argument:** Bug description or issue ID (required)
**Tools:** `search/codebase`, `edit/editFiles`, `execute/runInTerminal`, `execute/getTerminalOutput`, `read/problems`, `read/terminalLastCommand`, `vscode/askQuestion`
**What it does:**
- **Step 1 — Analyze:** Root-cause analysis, asks approval before touching code
- **Step 2 — Fix:** Applies targeted fix, writes to `09-bug-tracker.md`
- ❌ Never jumps straight to fixing without analysis

#### `#prompt:requirements-spec-enhance`
> Handle mid-execution scope changes and change requests

**Usage:**
```
#prompt:requirements-spec-enhance add rate limiting to the API
```
**Argument:** Change description (optional — will ask if missing)
**Tools:** `search/codebase`, `edit/editFiles`, `execute/runInTerminal`, `execute/getTerminalOutput`, `vscode/askQuestion`
**What it does:**
- Assesses impact on completed tasks, design, and pending work
- Asks impact approval via `vscode/askQuestion`
- Updates `06-requirements-spec.md`, `07-design.md`, `08-tasks.md`, `10-change-log.md`

#### `#prompt:requirements-status`
> Check current requirement progress and resume from checkpoint

**Usage:**
```
#prompt:requirements-status
```
**Tools:** `search/codebase`, `edit/editFiles`
**What it does:**
- Reads `.current-requirement` and `metadata.json`
- Displays phase, task progress, active bugs/changes
- Suggests next action based on current state

#### `#prompt:requirements-current`
> View full details of the active requirement session

**Usage:**
```
#prompt:requirements-current
```
**Tools:** `search/codebase`
**What it does:** Displays all requirement files (questions, answers, spec, design, tasks) in a structured summary.

#### `#prompt:requirements-list`
> List all requirement sessions with status indicators

**Usage:**
```
#prompt:requirements-list
```
**Tools:** `search/codebase`, `execute/runInTerminal`, `execute/getTerminalOutput`
**What it does:** Scans `requirements/` and `requirements/archived/`, shows phase and task progress for every session.

#### `#prompt:requirements-remind`
> Show phase-specific rules and reminders

**Usage:**
```
#prompt:requirements-remind
```
**Tools:** `search/codebase`
**What it does:** Displays the active rule set for the current phase — question limits, validation checklists, anti-patterns.

#### `#prompt:requirements-library`
> Manage the project knowledge library

**Usage:**
```
#prompt:requirements-library
#prompt:requirements-library init
#prompt:requirements-library view
#prompt:requirements-library query authentication
#prompt:requirements-library harvest
#prompt:requirements-library reset
```
**Argument:** Sub-command (optional — will ask if omitted)
**Tools:** `search/codebase`, `edit/editFiles`, `execute/runInTerminal`, `execute/getTerminalOutput`, `vscode/askQuestion`
**What it does:**
- **init** — Creates `requirements/.library/_catalog.json` if it does not exist
- **view** — Displays all Library Books grouped by shelf
- **query** — Searches the library for knowledge matching a keyword or topic
- **harvest** — Extracts reusable knowledge from the last completed session via the `curator` agent and stores it in the library
- **reset** — Permanently deletes all library data (asks for confirmation first)

**Library structure:**
```
requirements/.library/
├── _catalog.json          ← index of all books
└── [shelf]/[book].md      ← individual knowledge entries
```

## Session File Structure

Each session is a folder under `requirements/`:

```
requirements/YYYY-MM-DD-HHMM-feature-slug/
├── 00-initial-request.md       ← original feature description
├── 01-discovery-questions.md   ← phase 1 questions
├── 02-discovery-answers.md     ← phase 1 answers
├── 03-context-findings.md      ← autonomous codebase analysis
├── 04-detail-questions.md      ← phase 2 expert questions
├── 05-detail-answers.md        ← phase 2 answers
├── 06-requirements-spec.md     ← final requirements specification
├── 07-design.md                ← technical design (after specs-generate)
├── 08-tasks.md                 ← task breakdown (after specs-generate)
├── 09-bug-tracker.md           ← bug log (after bug-fix)
├── 10-change-log.md            ← change requests log
├── 11-change-backlog.md        ← deferred changes
└── metadata.json               ← phase, progress, status
```

**Phase values in `metadata.json`:**

| Phase | Meaning |
|-------|---------|
| `discovery` | Asking context questions (phase 1) |
| `context` | Autonomous codebase analysis |
| `detail` | Asking expert questions (phase 2) |
| `requirements_complete` | Spec ready, awaiting design generation |
| `specs_generated` | Design generated, awaiting approval |
| `design_approved` | Design approved, tasks pending |
| `specs_complete` | tasks ready, awaiting implementation |
| `executing` | Tasks being implemented |
| `implemented` | All tasks complete |
| `bug_fixing` | Bug fix in progress |
| `change_review` | Change request in progress |
